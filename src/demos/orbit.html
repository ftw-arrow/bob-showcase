The Three-Part Stack
Microsoft Copilot — The Front Door
The familiar chat interface your customers already use in Teams and Outlook. Built-in M365 trust, SSO, and data residency. Zero new tools for end users to learn. Copilot receives the natural language prompt and routes it to ORBIT.
IBM watsonx Orchestrate — The Intelligence & Governance Engine
The enterprise AI runtime that Copilot routes to. Chains tools, governs model inference, enforces policy, maintains a complete audit record of every AI action taken. Reads JSON mock data as enterprise system responses, fires live M365 actions via ARIA. Arrow AEC reference deployment on AWS now → ArrowSphere / Azure Q1 2027
R Co M365 Tenant — The Stage
Live Microsoft 365 environment (rcoace.com). 11 real personas with real inboxes, calendars, Teams channels. ARIA handles all Microsoft Graph API calls when ORBIT directs M365 actions. JSON mock files represent all enterprise back-ends — no live ERP/ITSM/HRIS required.
Real-World Data Patterns — Built for Proof
Every scenario runs on simulated production data — modelled on what your customers are already managing. The enterprise data powering each demo — help desk tickets, CRM account records, HR onboarding records, finance actuals — is structured to reflect the real data patterns Arrow AEC sees across customer engagements. This is not generic placeholder data. It mirrors the shape, fields, and relationships of the systems your customers are running today: ServiceNow, Salesforce, Workday, SAP. When a partner or customer is ready to go live, the simulated data is replaced with direct connector calls to their actual systems — the workflow logic, the governance rules, and the Copilot experience remain identical. The demo is the architecture. The architecture is the product.

Objection Handlers
❓ "Why not just use Copilot Studio / Copilot Agents?"
"Copilot Studio builds connectors — point-to-point integrations between Copilot and a specific API. If you need Copilot to read a SharePoint list, Copilot Studio is the right tool.

watsonx Orchestrate is not a connector. It is an enterprise AI runtime. In Scenario 4, Copilot Studio can call a finance API. It cannot read three data sources, identify exceptions based on policy, synthesise a variance narrative, route the approval to the right person based on org structure, and register the entire chain as a governed AI action — all from one prompt. That requires an orchestration engine, not a connector.

They complement each other. Copilot Studio for simple integrations. watsonx Orchestrate for multi-step enterprise workflows. Arrow deploys both."
❓ "IBM and Microsoft are competitors."
"Microsoft sells the collaboration and productivity surface — M365, Teams, SharePoint, Copilot. IBM sells the enterprise AI runtime — orchestration, governance, model lifecycle, regulated workflows. These are not the same market. The proof is that IBM built the Copilot integration. They built it because their customers asked for it. Arrow is the distributor that makes the combined stack deployable."
❓ "Is this available in Azure?" Be direct — don't hide the timeline
"The watsonx Orchestrate SaaS Copilot integration runs on AWS today. Azure availability is on IBM's roadmap for January 2027. Everything you see in Microsoft 365 — the inboxes, Teams, SharePoint, the Copilot surface — that is all Azure today. The orchestration engine moves to Azure in January. If your customer is Azure-first, January 2027 is the right engagement window — and what you're seeing now is exactly what it will look like."
❓ "What about the data — is this connected to a live system?"
"The enterprise back-end data in this demo — the ITSM tickets, account records, HR data, budget actuals — are portable JSON files ORBIT reads as tool responses. This is intentional. The demo runs anywhere, no VPN, no live back-end access, no security review. When Arrow deploys this for a real customer, we wire the same agent to their actual ITSM, CRM, or ERP system. The JSON is designed to be replaced with live data on day one of a real deployment."
❓ "Can we deploy this for our customers?"
"Yes. Arrow stands up the watsonx Orchestrate SaaS tenant, registers the Copilot extension in the customer's M365 tenant, builds the JSON mock files for their actual business processes, and delivers a working demo environment they own. We have done this. The environment you're watching right now is the deliverable."
